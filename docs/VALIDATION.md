本项目整理自一台 4×Tesla T10 16GB 的已运行原生部署，固定上游提交与 `UPSTREAM.json` 一致。以下为当时记录的结果，不是新目录安装后的验收报告：

- `/health` 返回 200，`/v1/models` 可查模型别名。
- 经 New API 的普通生成及 SSE 流式生成成功。
- MTP 草稿计数、接受计数和三个位置的统计增加。
- 约 45,036 token 的聊天输入返回预期短文本。
- 日志选择了 Firefly P2P TP4、FlashQLA-SM75 GDN prefill、NVFP4 INT8 快路径。
- 262,144 最大上下文、0.92 显存预算、MTP3 下，日志报告 KV 预算约 4.81 GiB/卡、543,326 token 池、满长请求理论并发容量 2.07x。

原服务后来进入 shutdown 并收到 SIGTERM；这不能单独证明存在内核崩溃，也不能表明它现在仍在线。本项目不收录真实运行日志、请求内容、密钥或私人主机地址。

以上证明 0.31 源码树在目标机可用，不等同于“从本仓库全新 clone 完成的干净安装验收”。本仓库的整理验收见下节。

## 整理项目的验收内容

- 配置白名单、数值边界、无 shell 执行、敏感参数不进命令行。
- MTP3 与 MTP0 参数分支。
- PID 重用、进程所有权检查、端口占用。
- Linux 下使用普通 sleep 子进程测试后台启动、防重复启动、停止；不加载模型。
- 全部 Python 源码语法、Bash 语法、来源校验和、公开文件排除与基础敏感扫描。
- CI 仅包含以上无 GPU 检查；不把缺少 GPU 的成功 CI 解释为 CUDA 验收。
